# 每日新手禮包自動化

本專案由 Windows 工作排程器依 Asia/Taipei 每日 07:00 處理前一個日曆日的新註冊會員。每個品牌依序執行：後台匯出 → 試算表既有 Apps Script 分組與 LINE CSV 下載 → 清理品牌工作表 → 建立 18:00 生效的遊戲內免費禮包 → 更新 LINE UID 受眾。受眾變成「可用」後，另一個排程才預約 18:00 推播並回報 TG。進度與失敗原因寫入 `state/runs.json` 及 `logs/`。

## 目前可用範圍

2026-09-23 註冊名單已於 09-24 完成三品牌遊戲禮包、LINE 受眾與各品牌工作表清理；三筆 LINE 18:00 推播由使用者手動預約後，執行器已逐筆核對預約時間與唯一受眾並回填完成狀態。新批次的 UID 受眾仍可能停在「準備中」；禮包與受眾完成後先記錄 `awaiting_audience`，不重寄禮包。

## 開始使用

1. 禮包專用 Chrome 保持登入 Google 試算表與三個 LINE OA 帳戶；三個遊戲後台可使用此視窗或營運專案的第二個專用 Chrome。排程在視窗未開時會用既有設定檔啟動兩個視窗；若網站登入過期，執行器會停止，不會猜測帳密或重送。
2. 乾跑指定註冊日期：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-daily.ps1 -Date YYYY-MM-DD -VerifyOnly`。這會匯出與處理工作表，並在提交禮包／LINE 之前停下。
3. 正式執行：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-daily.ps1`。未指定日期時自動選台北時間昨天；已完成批次會直接略過。
4. 查看 `state/runs.json` 與當日 `logs/YYYY-MM-DD.log`。若狀態為 `needs_review`，請先核對平台是否已送出，勿直接重跑。

## Google 試算表登入

`open-automation-chrome.cmd` 以一般 Chrome 和專用設定檔開啟視窗，並只在本機 `127.0.0.1:9222` 提供程式控制介面。已實測這個視窗能正常登入 Google 試算表與三個 LINE OA。若遊戲後台在此視窗的登入過期，匯出與寄送會改連營運專案已登入的 `127.0.0.1:19385` 視窗。`open-google-chrome.cmd` 則是同一設定檔的純手動 Chrome 視窗；兩者不能同時使用同一設定檔。

目前的試算表程式會直接操作既有選單函式，不需要改寫 150 門檻邏輯。`src/google-check.js` 保留作為未來可選的正式 OAuth 路徑；目前流程並不要求使用者建立 OAuth 客戶端。

## 排程

`install-schedule.ps1` 建立目前使用者工作排程器的「每日三平台新手禮包執行器」，每日 07:00 啟動 `run-daily.ps1`。`install-broadcast-retry.ps1` 建立 `DailyGiftLineRetry`，從 07:05 起每 5 分鐘檢查一次待預約的 LINE 受眾；先核對是否已有人預約，避免重複。初次上傳超過 5 分鐘仍準備中時，僅在確認尚無預約、受眾仍準備中且只有一筆同名資料後刪除原筆並重傳一次。重傳後繼續等到受眾可用才預約當天 18:00 推播；17:15 仍不可用就標記待核對並通知 TG，不會無限刪建。兩個工作都設定喚醒、錯過時間後補跑與電池供電時繼續執行，並使用互動式登入工作階段；電腦須開機且目前使用者仍登入 Windows。

重開機後先登入 Windows 即可讓排程繼續；07:00 程式會啟動缺席的既有專用視窗。若 Google、LINE 或後台顯示登入頁，須在該專用視窗手動完成網站登入，程式不會操作登入欄位。保留兩個瀏覽器設定檔與本機連接埠設定，才能沿用已登入工作階段。

同一對話先前建立的 Codex 自動任務已改為每日 07:30 **只讀檢查結果**，不再執行任何派送，避免與 Windows 排程重複寄送。

## Telegram 通知

已建立 Bot **小精靈工作回報**（`@yingma_songbao_qiezi_bot`），加入群組 **小精靈的日常回報**，並實測群組收到連接成功訊息。`telegram.local.json` 保存 Bot token 與群組 chat ID，ACL 只允許目前 Windows 使用者存取，且已列入 `.gitignore`。使用者不必每天重新設定；若未來更換 token 或通知群組，可於本機 PowerShell 執行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup-telegram.ps1`。程式會隱藏 token 輸入、列出 Bot 收到的群組／私人對話供選擇，並送出測試訊息。不要將 token 貼到聊天或提交版本控制。

07:00 禮包及 LINE 受眾完成後，TG 會收到三品牌進度摘要。LINE 受眾仍在準備時會顯示等待；候補排程確認 18:00 推播後會再回報完成。有品牌失敗或待核對時會收到異常摘要。相同批次與結果的通知只發一次，記錄在 `state/telegram-notifications.json`。未設定或通知送出失敗時，禮包進度仍保留，但排程回報失敗，供後續檢查。乾跑與指定歷史日期不會發 TG；指定日期需要通知時可用 `node src/daily-runner.cjs --date=YYYY-MM-DD --notify`。

同一隻 Bot 之後可供其他專案使用不同群組 chat ID 發送通知；Bot token 可控制整隻 Bot，應由統一通知服務管理，不必分發給每位同事。

現已讓另一個「營運數據自動更新」專案的 08:00 排程共用此 Bot 與群組，並驗證測試訊息送達；兩個排程各自回報，不互相重跑工作。

## 防重與失敗處理

程式以註冊日期／品牌為批次鍵；已完成批次不重做。對外寄送前先寫入 `in_progress`，記錄正在執行的動作；若送出結果不確定，標記 `needs_review`，不自動重送。`awaiting_audience` 表示禮包與受眾已完成，但推播尚未預約，候補排程可安全再檢查。每個品牌的試算表處理完都會點「使用完畢，清理表格」，並驗證會員與輸出儲存格已清空。登入失效或提交失敗時，只停止該品牌並留下日誌。
