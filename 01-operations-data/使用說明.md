# 三平台營運表固定程式

## 現行設定（2026/9/23）

只保留既有 Windows 工作 ThreePlatformOperations0800，每天台灣時間 08:00 執行。週一在同一程序處理上一完整週機台報表，其他天只日更；不是每日填未結束的本週。config.json 的 enabled 與 weeklyEnabled 均為 true。獨立 Codex 週更及本次一次性驗收排程已暫停，不要建立重複排程。

專用 Chrome 沿用本機控制 127.0.0.1:19385。08:00 排程若發現視窗未開，會用既有設定檔先啟動視窗；07:00 新手禮包排程也會嘗試提早啟動。不要重建設定檔或同時開第二個控制程序。程式只關閉自己建立的分頁，不關閉使用者既有視窗。若網站登入失效，程式會用「設定後台帳密.cmd」存下的加密帳密自動輸入並登入（見下方「後台帳密（自動重新登入）」）；仍失敗時才改用備用視窗或停止並通知，使用者可在此視窗手動重新登入。程式不記錄、不輸出帳密，也不要求使用者傳送帳密。不要分享 private 或瀏覽器設定檔。

固定程式不呼叫 AI 模型。電腦、網路及已登入 Windows 的使用者工作階段必須可用；網站登入失效時仍須重新登入。已讀取 Windows 工作排程器：單一工作 `ThreePlatformOperations0800` 每天 08:00 執行。排程命令仍含歷史參數 `--daily-only`，但 `--scheduled` 在週一會依 `schedule-policy.mjs` 加做上一完整週機台週更。

### Telegram 回報

08:00 的正式排程已接上 **小精靈工作回報** Bot，送到 **小精靈的日常回報** 群組；群組已收到通知連線測試。三平台全部讀回核對完成會送成功摘要；若任何平台失敗或有警告，會列出已完成的平台與失敗原因，提醒先核對可能已更新的表格。通知依當次執行的記憶體狀態與 `runId` 產生，不使用可能被後續手動補跑覆蓋的 `logs/latest.json`。通知紀錄在 `private/telegram-notifications.json`，同一次結果不重送。

Bot token 只存於新手禮包專案的使用者限定設定檔；此專案的 `config.json` 僅保存設定檔路徑。`node telegram-notify.mjs --test` 可單獨送出一則連線測試，不更新任何報表。一般手動更新不自動發 TG；需回報時可在 `run.mjs --apply` 加 `--notify`。

08:00 排程若有平台失敗，會在 2 分鐘後只補跑失敗平台，最多補跑 2 次；已讀回核對完成的平台沿用當次結果，不重複寫入。若啟動階段整體失敗且三平台都尚未開始，也會在 2 分鐘後重試整次排程，最多 2 次。補跑仍依當日紀錄與現有表格重新核對後才寫入。每次補跑的 Telegram 通知會更新同日狀態，完成通知會取代先前的失敗通知。若紀錄缺漏、平台有警告、執行逾時或已跨日，程式會停止自動補跑並保留失敗結果供人工檢查；不會無限重試。

## 後台帳密（自動重新登入）

後台閒置約 2 小時會登出。雙擊 **設定後台帳密.cmd**，先回答「三個後台是否使用同一組帳密？(Y/N)」：Y 只輸入一次帳號與密碼，套用到贏麻了、爽爆、茄子；N 逐一輸入各後台（直接按 Enter 保留原本設定）。密碼輸入時不顯示，需輸入兩次確認；結束時只列出哪些後台已設定，不顯示密碼。

- 加密檔：`private\backend-credentials.dpapi.json`。帳號與密碼都用 Windows DPAPI（目前使用者）加密，只有這台電腦上的 Windows 帳號 `User` 能解開；檔案權限也只開放給此帳號。換電腦或換 Windows 帳號後需重新設定。不要分享或複製這個檔案。
- 更新：後台密碼變更後，再雙擊一次 設定後台帳密.cmd 輸入新密碼即可（N 模式可只改其中一個後台）。
- 登入流程：遇到登入頁先重新整理，再清空並逐字輸入帳號、密碼，確認兩欄都有內容後只按一次「登入」，並確認已離開登入頁且後台接受工作階段；失敗會再重試一次，仍失敗才停止並記錄截圖（截圖前會先清空帳密欄位）。成功時 TG 會寫「後台登入逾時，已自動重新登入」。
- 若尚未設定或檔案無法解開，會顯示「尚未設定後台帳密，請執行 設定後台帳密.cmd」，並照舊嘗試備用視窗（9222）讀取；備用視窗只讀取，不會在那裡輸入帳密。
- 測試自動登入：`node run.mjs --no-fallback`（試跑不寫入、停用備用視窗，可證明是本程式自行登入）。`設定後台帳密.cmd -SelfTest` 只用假資料測試加解密，不寫入正式加密檔。
- 其他程式要重用：執行 `powershell -NoProfile -ExecutionPolicy Bypass -File backend-credentials.ps1 -Decrypt -Platform <win|song|qz|後台名稱|網址主機>`，標準輸出是 UTF-8 JSON `{"username","password"}` 的 base64；結束碼 2＝沒有檔案、3＝該後台未設定、4＝無法解開。必須以同一個 Windows 帳號執行，且不可把結果寫入檔案或記錄。

## 使用

- 立即更新.cmd：更新並讀回驗證，請勿在既有更新尚未結束時重複開啟。
- 試跑不寫入.cmd：查詢及下載唯讀快照，計算計畫，不寫報表。
- 檢查登入.cmd：檢查登入狀態。
- 安裝早上8點排程.cmd：目前已有排程，不要重複安裝。

logs/latest.json 記錄最新執行及各步驟是否完成；private/runs 保存來源、寫入計畫與前後快照。completed=false 代表部分完成或失敗，不代表完全沒有寫入。補跑先依日期與週標籤定位，不能再追加相同日期或週區塊。

## 執行順序與保護

每平台先查詢日更來源，核對並更新週報日更及月摘要，再核對營收總表與幣商金幣統計，最後於週一查詢及寫入機台週更。週更失敗不再阻擋該平台營收總表；各平台分開記錄失敗。

每月 1 日同一排程自動走跨月流程：導出上個完整月會員清單並完成渠道分析；從玩家紀錄的上月最後一天金幣紀錄取得各幣商最後一筆「異動後」；按需新增週報及營收總表的新月份幣商區塊；新增營收總表第一頁月份列並依歷史公式間距更新所有幣商引用；再寫入新月 08:00 當下的營收、有效投注及幣商餘額。全部平台成功後才把 approvedMonth 推進到新月。任一平台失敗可安全重跑，不重複新增。

每月 2 日只在週報「總表」A:J 每日明細區裁掉前前月，將上月移到區塊起點並接續新月 1 日；右側會員分析及其他歷史區塊不動。3 日起回到一般日更。月初不建立第二個排程。

新增列先確認實際列界線，只補足不足列數；新週使用實際插入欄選單在最左側新增 12 欄，同週重跑沿用既有區塊。日期、明細及 C1/E1/G1 公式均須匯出讀回一致。保留原檔與無關歷史資料，不轉檔或整本重建。

留存從上個月 1 日到昨天；新增會員及平均 DAU 到昨天。月營收及有效投注額為查詢當下本月累計，不能用昨日每日加總替代。幣商在週報四捨五入，營收總表保留原始小數。

approvedMonth 僅核准 2026-09。未核准月份及月初結算仍有保護，不能自行改月份或猜月結口徑。跨月前須由使用者確認規則與位置；此邊界不能標示為全面驗證完成。

private/run.lock 防止主程式重複執行。異常關機留下鎖檔時，必須先確認沒有程序在跑，才可人工處理；不要任意刪除鎖檔。修復前 sheets.mjs 及 run.mjs 備份保留於同資料夾 *.bak-20260921-fix。測試使用 npm test 或 node --test。
